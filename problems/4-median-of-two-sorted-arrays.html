LeetCode #4 Hard Binary Search on Partition

Median of Two Sorted Arrays

“Cut the short one, cross-check the edges.”

You get two sorted arrays, nums1 (length m) and nums2 (length n). Return the median of all m + n values combined, in O(log(m + n)) time.

Key idea: you don't need to merge. A median splits the combined values into a left half and a right half where every left value is ≤ every right value. Pick how many values the shorter array puts on the left. That choice forces how many the longer array gives, so you binary search that one number.

1 · Swap

Search the shorter array

If A is longer than B, swap them. Fewer cut positions, and j never goes out of range.

2 · Cut

i from A, j = half − i from B

Set i to the middle of the search range. B has to fill the rest of the left half.

3 · Cross-check

Aleft ≤ Bright and Bleft ≤ Aright

Each side is already sorted, so only the four values next to the cuts need comparing.

4 · Shift

Move toward the violation

If Aleft is too big, move the cut left (hi = i − 1). Otherwise move it right (lo = i + 1).

5 · Answer

Read the median off the edges

If the total is odd, take max(lefts). If it's even, average max(lefts) and min(rights).

def findMedianSortedArrays(nums1, nums2):    A, B = nums1, nums2    if len(A) > len(B):        A, B = B, A    m, n = len(A), len(B)    half = (m + n + 1) // 2    lo, hi = 0, m    while lo <= hi:        i = (lo + hi) // 2        j = half - i        Aleft  = A[i-1] if i > 0 else float('-inf')        Aright = A[i]   if i < m else float('inf')        Bleft  = B[j-1] if j > 0 else float('-inf')        Bright = B[j]   if j < n else float('inf')        if Aleft <= Bright and Bleft <= Aright:            if (m + n) % 2:                return max(Aleft, Bleft)            return (max(Aleft, Bleft) + min(Aright, Bright)) / 2        elif Aleft > Bright:            hi = i - 1        else:            lo = i + 1

Why it's fast

  • One number decides everything. The left half always has half = (m+n+1)//2 values. Once you pick i, you know j. The search space is just the m + 1 possible values of i.
  • The check is monotone. If Aleft > Bright, any larger i makes Aleft bigger, so the answer is to the left. If Bleft > Aright, the answer is to the right. That's what makes binary search valid here.
  • Sorted order does most of the work. Inside each array, left ≤ right already holds. Only the two cross comparisons can fail.
  • ±∞ sentinels handle cuts at an array's very start or end, so there are no special cases.
