LeetCode #9 Easy Math · Half-Reversal

Palindrome Number

"Fold it in half: peel the tail backward. If it matches the head, it's a palindrome."

Given an integer x, return true if it reads the same forward and backward. For example, 121 is a palindrome but -121 is not (it reads 121- backward). Follow-up: solve it without converting to a string. The trick is to reverse only the second half of the digits and compare that with the first half.

Move 1 · Guard

Reject impossible shapes

x < 0 or (x % 10 == 0 and x ≠ 0) → False

A minus sign can't mirror. A trailing 0 would need a leading 0, which no number has.

Move 2 · Peel

Pop the last digit

d = x % 10; x //= 10

Take the digit off the tail of x. That makes the front half shorter.

Move 3 · Push

Build the reversed tail

rev = rev * 10 + d

Shift rev left one place and append the digit, so the tail builds up in reverse.

Move 4 · Halt

Stop at the middle

while x > rev

Once rev catches up to x, half the digits have been reversed. There's no need to go further.

Move 5 · Compare

Match the halves

x == rev or x == rev // 10

With an even digit count the halves must be equal. With an odd count, drop the middle digit from rev first.

Why it's fast

Key insight: A palindrome's second half, read backward, is its first half. So we reverse only half of the number. Because we remove digits from x as we add them to rev, the moment x ≤ rev tells us we've reached the middle, without ever counting digits.

  • We never build a string, so no extra memory is needed.
  • Reversing only half means rev never exceeds about √x, so it can't overflow. Fully reversing a 32-bit int (e.g. 2147483647) can overflow.
  • The trailing-zero guard is required. Without it, 10 would halt at x = 1, rev = 0, and rev // 10 = 0 ≠ 1 works only by luck. For inputs like 110, dividing out the zero would give a wrong answer.
